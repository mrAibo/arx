# ARX Secret Storage

ARX never stores secrets in its own configuration or logs. This document is the
authoritative truth about where each credential class lives.

## File map

| File | Owner | Stores | Permissions |
|------|-------|--------|-------------|
| `~/.config/arx/arx.toml` | ARX | normal config + S3 target **metadata** (no secrets) | 0600 |
| `~/.config/arx/hosts.toml` | ARX | ARX host metadata (no passwords / private keys) | 0600 |
| `~/.ssh/config` | **user** | OpenSSH client config (user-owned) | 0600 |
| `~/.ssh/arx_hosts.conf` | ARX | ARX-managed SSH entries (IdentityFile **path only**) | 0600 |
| `~/.ssh/arx/` | ARX | SSH private-key files (`*.pub` alongside) | dir 0700, key 0600 |
| `~/.aws/*` | AWS CLI | AWS credential/profile sources (e.g. `~/.aws/credentials`) | 0600 |
| OS keyring | OS | SSH passwords (if any) | OS-managed |

## SSH secrets

- **Private keys** live as files under `~/.ssh/` (ARX default `~/.ssh/arx/`).
  ARX writes them only via `ssh-keygen`; it never implements cryptography.
- **IdentityFile** in `~/.ssh/arx_hosts.conf` stores the **path** to a key, never
  the key bytes. ARX never reads, prints, or logs private-key material.
- **Passphrases** are **not stored by ARX**. Keys generated by ARX are created with
  an empty passphrase (`ssh-keygen -N ""`). If a user supplies a passphrase, it
  must live in the SSH agent or OS keyring — never in ARX config.
- **Passwords** for SSH (interactive) are stored in the OS keyring **through ARX's
  keyring integration** when managed by ARX. OpenSSH itself does not read ARX's
  OS-keyring entry; ARX resolves the password and supplies it to the connection.
  Password bytes are never written to `hosts.toml`, `arx.toml`, or the SSH config.

## AWS / S3 secrets

- `S3TargetConfig` stores only: `id`, `name`, `bucket`, `region`, `profile`,
  `endpoint_url`, `force_path_style`. **No access keys, secrets, tokens, or
  session tokens.**
- AWS credentials are resolved by the standard AWS credential chain
  (`~/.aws/credentials`, env, IMDS, SSO) — outside ARX product config.
- ARX `Debug`/`Display`/error output redacts `endpoint_url` to `<configured>` and
  never prints secret/token/signed-query material.

## Managed config safety

- ARX installs **at most one** `Include ~/.ssh/arx_hosts.conf` line into the
  user-owned `~/.ssh/config`. It never rewrites unmanaged `Host` blocks, never
  removes user comments, and never creates duplicate `Include` lines.
- The first mutation of `~/.ssh/config` is backed up to
  `~/.ssh/config.arx-backup`.
- Wildcard aliases (`*`, `?`) are rejected. Aliases with newlines or control
  characters are rejected.
- A new managed alias that collides with an existing (unmanaged) alias fails
  closed — ARX refuses to write.

## Verification

Run `cargo test --locked --all-features` — the `ssh_config_manager_tests`
suite asserts: include-installed-once, collision-fail-closed, managed file
stores path only (no `BEGIN`/`PRIVATE KEY`), and alias rejection.
