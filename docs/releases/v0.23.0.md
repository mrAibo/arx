# ARX v0.23.0

v0.23.0 ships the read-only **S3 Object & Bucket Inspector** completed after
v0.22.0. It adds exact object metadata inspection and bounded, paginated
bucket/prefix analytics while keeping S3 truth separate from POSIX filesystem
capacity semantics. MSRV remains **Rust 1.88**; ARX remains Linux-only with the
published **Linux x86_64** target.

The immutable tag and live GitHub Release state remain authoritative for actual
publication; this release note does not infer publication merely from source-tree
version metadata.

## Highlights

### Exact S3 object inspection

For one exact provider-native S3 object, ARX uses `HeadObject` and reports only
facts the backend actually returns.

- Exact target, bucket, and key identity remains authoritative.
- Size, last modified, ETag, content type, storage class, metadata, endpoint
  override, and version ID are shown only when available from the provider.
- Missing values remain unavailable rather than being synthesized.
- Inspection is read-only and does not create a new S3 mutation path.

### Bounded bucket / prefix LiveScan

Bucket and prefix inspection uses paginated `ListObjectsV2` evidence rather than
pretending object storage is a mounted filesystem.

- Pagination uses continuation tokens with defensive checks against contradictory
  or non-advancing responses.
- The scan reports observed object count and logical bytes.
- Largest-object ranking is bounded.
- Immediate-prefix analysis is bounded and retains truthful unavailable/partial
  state when exact ranking cannot be kept within the bound.
- Age distribution and storage-class distribution are derived from observed
  provider facts.
- Prefix cardinality and storage-class cardinality are explicitly bounded, so an
  unusual or very large S3-compatible backend cannot turn the inspector into an
  unbounded in-memory inventory.
- Progress and cooperative cancellation are supported.
- Error or cancellation preserves truthful partial scan state instead of
  fabricating completion.

### Existing authority model retained

The S3 Inspector reuses the existing `ProviderRegistry`, per-target `S3Provider`
and lazy AWS client, `JobManager`, and UI authority. It does **not** introduce a
second provider registry, S3 client cache, scheduler, retry engine, JobManager, or
secret store.

`Alt+U` remains one Storage Inspector entry point: Local locations use the Local
usage inspector, while supported S3 locations use exact object or bounded
bucket/prefix inspection.

## Physical acceptance

The accepted implementation was validated on the exact feature head and again on
merged `main` with the standard quality and Rust 1.88 MSRV gates plus the affected
physical lanes.

- Real MinIO acceptance explicitly exercises `tests/s3_inspector_minio.rs` and
  proves the object and prefix inspector path.
- AWS S3 remains the supported S3 product path.
- MinIO remains physically accepted.
- Cloudflare R2 and Wasabi remain best-effort/unverified until separately
  evidenced; this release does not claim certification for them.
- Existing Apache WebDAV and real tmux/GNU Screen PTY regression lanes remained
  green on the accepted S3 feature and merged main.

## Safety boundaries retained

- The S3 Inspector is read-only.
- No cleanup, lifecycle-management, or destructive S3 workflow is added here.
- ARX does not fabricate capacity, free-space, inode, or `df` semantics for S3.
- ARX does not invent storage billing or cost estimates.
- Provider-native existing-resource identity remains authoritative; display text
  does not reconstruct remote addresses.
- Existing transfer, job, retry, provider, and secret authorities remain singular.
- WebDAV automatic HTTP mutation retry remains disabled and ambiguous remote
  mutations remain non-replayable by default.

## Retained from v0.22.0

v0.23.0 retains the accepted WebDAV recursive-operation surface from v0.22.0,
including recursive Local → WebDAV upload, safe bounded recursive WebDAV delete,
recursive WebDAV → Local download, and one-job multi-root Local ↔ WebDAV F5 Copy.
No configuration migration is required for those workflows.

## Not in this release

- SFTP → SFTP workspace synchronization.
- WebDAV → WebDAV recursive/cross-target copy or move.
- Multi-root recursive WebDAV delete.
- General cross-provider Move.
- Digest/Bearer WebDAV auth without concrete interoperability need.
- Metadata/property mutation without a demonstrated admin use case.
- S3 cleanup/lifecycle management or fabricated cost/capacity analytics.

## Installation

Download your preferred artifact and `SHA256SUMS` from the GitHub Release and
verify:

```bash
sha256sum --ignore-missing -c SHA256SUMS
```

```bash
# Debian / Ubuntu
sudo apt install ./arx_0.23.0_amd64.deb

# Fedora / RHEL family
sudo dnf install ./arx-0.23.0-1.x86_64.rpm

# Portable tarball
tar xzf arx-v0.23.0-x86_64-unknown-linux-gnu.tar.gz
sudo install -m 755 arx-v0.23.0-x86_64-unknown-linux-gnu/arx /usr/local/bin/arx
```

Expected version output:

```text
arx 0.23.0
```

No configuration migration is required from v0.22.0.
