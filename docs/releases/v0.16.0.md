# ARX v0.16.0

## S3 object storage — Release Candidate

ARX adds an S3 object-storage backend as a **release candidate**. It targets
MinIO-style S3-compatible endpoints and AWS S3 via the standard credential
chain (profile / env / IMDS).

### What works (truth-classified)

- **Target / bucket / prefix navigation** — browse S3 like a filesystem tree.
- **Pagination** — incremental, bounded, stale-safe (no eager full-bucket load).
- **F3 bounded preview** — range GET, preview-size capped.
- **Local ↔ S3 single-object F5** — upload / download one object.
- **Multipart upload** — sequential part PUT, cancel truth, part-count progress.
- **Staged S3 download** — streamed GET, staging, fsync, atomic rename.
- **F7 prefix marker** — create empty prefix marker (mkdir-equivalent).
- **F8 exact object / proven-empty marker delete** — one `DeleteObject`.

### Acceptance status

| Lane | Result |
|------|--------|
| MinIO (live `arx-minio-test`) | **PHYSICAL PASS** (S3-66/67, byte-exact roundtrip) |
| Moto / LocalStack (AWS-shaped emulator) | **EMULATED PASS** (S3-62E..65E) |
| Real AWS S3 | **BLOCKED** — no disposable real-AWS environment available |

Real AWS physical acceptance is the **only** external release blocker. ARX
S3 is **not** claiming AWS-physically-certified support.

### Explicitly unsupported

- S3 F4 (EditFile) — stays fail-closed
- S3 F6 (rename)
- recursive S3 prefix delete
- bucket create / delete
- S3 → S3 transfer
- SFTP ↔ S3 transfer
- Workspace Sync with S3

Capability surface is frozen to:
`List + Read + Write + Mkdir + Delete` only.

## Upgrade notes

- No config-breaking changes for existing Local / SFTP / Archive workflows.
- S3 targets are opt-in via `arx.toml` (`[s3_targets]`); no credentials stored
  in config — standard AWS credential chain is used.
- MSRV remains **Rust 1.88**.
