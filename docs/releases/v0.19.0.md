# ARX v0.19.0

v0.19.0 is the **Transfer Queue release**. It promotes the merged PACK G transfer
orchestration from implementation status to a released user-facing capability while
keeping the v0.18.0 WebDAV release as the backend baseline.

MSRV remains **Rust 1.88**. The published artifact remains **Linux x86_64**. ARX is
intentionally Linux-focused; native Windows support is not planned.

## Highlights — Transfer Queue

- **Persistent background queue** for supported Copy/Move transfer plans.
- **Bounded FIFO scheduling** with default concurrency **N=2**.
- **Configurable concurrency** through `[transfer] concurrency`, valid range `1..=8`.
- **One JobManager lifecycle truth** for pending, running, pause-pending, paused,
  retry-waiting, cancelling, cancelled, failed, and completed states.
- **Truthful status-bar progress** for the primary running transfer.
- **Byte rate and ETA** only where the provider can support those facts.
- **Unknown totals remain unknown**; ARX never renders an unknown total as zero.
- **Ctrl+Y Transfer Center** for the active transfer queue.
- **Pause / Resume / Cancel** integrated with Jobs for transfer jobs.
- **Cooperative same-task Pause/Resume** at safe checkpoints with the same JobId and
  same execution attempt.
- **Bounded automatic safe retry**, maximum **3 total attempts**.
- **No blind replay of ambiguous mutations**: only failures classified
  `SafeToRetry` are replayed automatically.
- **Explicit recovery truth**: `AmbiguousMutation` and `RecoveryRequired` are not
  disguised as ordinary retriable failures.
- **Owned shutdown**: workers and retry timers are joined so shutdown does not leave
  detached mutations behind.

The queue orchestrates already-supported TransferPlanner paths. v0.19.0 does **not**
claim new cross-provider transfer combinations merely because the queue exists.

## Transfer configuration

The existing configuration section is:

```toml
[transfer]
concurrency = 2
```

The default is `2`; accepted values are `1..=8`.

## Physical acceptance

PACK G was accepted against real I/O and real provider fixtures.

- **P1 — concurrency:** two real transfers overlap with `N=2`.
- **P2 — FIFO waiting:** a third transfer stays queued until a slot is released.
- **P3 — cancel isolation:** cancelling one active transfer does not cancel unrelated
  work.
- **P4 — real pause/resume:** `Running -> PausePending -> Paused -> Running ->
  Completed` through a real executor checkpoint.
- **P5 — paused stability:** completed progress remains unchanged while truly paused.
- **P6 — resume identity:** the same JobId and execution attempt continue after
  resume; progress is not reset.
- **P7 — terminal truth:** completed output and progress are byte/item exact.
- **P8 — real safe-read retry:** a real MinIO `GetObject` response is truncated by a
  one-shot TCP fault proxy after response headers and an 8 KiB body prefix. The first
  body read fails, the staged `.arx-part-*` file is removed, the job enters
  `RetryWaiting`, and the second GET succeeds. Observed GET count is exactly 2; the
  final destination is byte-exact and no staged artifact remains.
- **P9 — WebDAV ambiguous mutation:** real Apache `mod_dav` evidence proves one PUT
  attempt; the queue never blindly replays the ambiguous mutation.
- **P10 — SFTP commit/rename ambiguity:** real OpenSSH SFTP provider evidence plus the
  queue's typed disposition preserves one-shot mutation behavior.
- **P11 — shutdown:** active/paused work settles and owned workers/timers are joined;
  no detached mutation continues after shutdown.
- **P12 — artifact cleanup:** no unexplained `.part`, `.partial`, `.tmp`, or
  `.arx-*` transfer artifacts remain after accepted paths.

The dedicated CI job `transfer-queue-s3-retry-physical` continuously exercises the
real MinIO P8 safe-read retry path. The existing `webdav-physical` job continues to
run Apache `mod_dav` W1–W18 acceptance.

## Safety boundaries

- Automatic replay is allowed only for explicit `SafeToRetry` outcomes.
- `AmbiguousMutation` is never blindly retried.
- `RecoveryRequired` remains an explicit operator-visible recovery outcome.
- Unknown transfer totals are not converted to zero and do not produce fake percent
  or ETA values.
- Terminal jobs remain terminal; completed/cancelled/failed truth is not rewritten by
  later queue activity.
- Shutdown owns and joins queue workers/retry timers instead of abandoning detached
  mutations.

## Inherited v0.18.0 baseline

v0.19.0 retains the v0.18.0 backend baseline unchanged, including:

- WebDAV Basic-auth supported MVP with Apache `mod_dav` W1–W18 physical acceptance;
- AWS S3 and MinIO supported MVP status, with Moto emulated acceptance;
- SFTP Remote Edit reliability/safety hardening;
- managed SSH Host Manager;
- Rust 1.88 MSRV.

## Deferred / not claimed

The following are intentionally **not** part of the v0.19.0 release claim:

- Native Windows support. ARX remains a Linux application; Windows issue #17 is closed
  as not planned.
- New unsupported cross-provider transfer combinations.
- A manual retry button or manual terminal-job clearing workflow; automatic retry is
  the released queue behavior.
- WebDAV Digest/Bearer authentication.
- WebDAV F4 remote edit.
- recursive WebDAV transfers/delete or cross-target WebDAV move.
- Nextcloud / ownCloud physical certification.
- SFTP → SFTP workspace synchronization.

## Upgrade

No migration is required for existing v0.18.0 users. Existing configurations remain
valid. To tune queue concurrency, add the optional `[transfer]` section shown above.

After installation:

```bash
arx --version
```

must report:

```text
arx 0.19.0
```
