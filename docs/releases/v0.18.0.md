# ARX v0.18.0

v0.18.0 is the WebDAV release. It promotes the merged PACK E backend from candidate status to a **supported MVP** while keeping the v0.17.1 reliability hardening as the baseline.

MSRV remains **Rust 1.88**. The published artifact remains Linux x86_64.

## Highlights — production WebDAV backend

- **Production WebDAV `VfsProvider`** using `reqwest` + `quick-xml`.
- **DAV operations:** PROPFIND, GET, PUT, DELETE, MKCOL, COPY, and MOVE.
- **HTTP Basic authentication** with password resolution from the OS keyring or `ARX_WEBDAV_<ID>_PASSWORD`; plaintext passwords are never stored in `arx.toml`.
- **F3 bounded preview** for WebDAV files.
- **F5 one-file Local ↔ WebDAV transfer** through the shared transfer planner/executor path.
- **Authoritative raw-href identity:** operations use the server-provided href rather than reconstructing an address from a display name.
- **Strict DAV XML semantics:** namespace-aware, propstat-aware parsing with bounded response/property/text accumulation and fail-closed malformed/oversized handling.
- **Atomic remote no-clobber:** overwrite-forbid PUT uses `If-None-Match: *`; an existing destination is surfaced as `AlreadyExists` without a HEAD/PROPFIND overwrite preflight.
- **Local download no-clobber:** WebDAV downloads stage in a secure temporary file in the destination directory and finalize with real noclobber semantics.
- **No blind replay:** automatic HTTP retries and redirects are disabled for the WebDAV client; ambiguous mutations return a truthful error rather than being replayed.
- **Cancellation-safe streaming:** cancellation is checked while streaming and again before final local persistence; failed/cancelled downloads do not leave a partial final file.

## Physical WebDAV acceptance

The headline backend is guarded by the dedicated `webdav-physical` CI job using a real Apache `mod_dav` fixture.

**W1–W18: PASS** for the accepted PACK E implementation, including:

- production secret-resolution/authentication path;
- listing, navigation, Unicode/spaces, bounded preview;
- Local → WebDAV and WebDAV → Local product transfer paths;
- MKCOL / COPY / MOVE / DELETE;
- bad credentials and truthful 404 mapping;
- atomic overwrite conflict with exactly one product PUT and no overwrite preflight;
- real Apache LOCK → 423 `PermissionDenied` → UNLOCK cleanup;
- truncated real-Apache GET response with no retry, partial final file, or leaked stage;
- ambiguous PUT where Apache processed the request but ARX did not learn the outcome, proving one PUT and no replay.

Apache `mod_dav` is therefore **PHYSICAL PASS / SUPPORTED MVP**.

## Security and safety boundaries

- Passwords are resolved from keyring/environment and are not persisted in normal configuration.
- Diagnostic URLs do not expose passwords.
- Raw WebDAV hrefs are origin/root constrained; traversal, userinfo, fragments, and cross-origin identities fail closed.
- Raw percent-encoding and query identity are preserved for authoritative same-origin hrefs.
- WebDAV XML namespace-less or non-DAV same-local-name elements do not drive DAV protocol state.
- Error/status mapping remains explicit, including 412 conflict and 423 locked.

## Inherited v0.17.1 baseline

v0.18.0 includes the v0.17.1 reliability work unchanged, notably:

- transport-only SFTP connection invalidation;
- bounded pooled-session health probes and deterministic stale reconnect;
- no destructive mutation replay;
- Remote Edit lifecycle integration with the Job Manager;
- lane-isolated failure handling;
- deterministic fault-injection and recovery evidence;
- writable-parent safety policy and physical SFTP Remote Edit acceptance.

This release does not change the S3 or SFTP behavior contracts as part of the WebDAV release pack.

## Deferred / unsupported in the WebDAV MVP

The following are intentionally **not** claimed by v0.18.0:

- Digest or Bearer WebDAV authentication;
- WebDAV F4 remote edit;
- recursive WebDAV transfers or recursive remote delete;
- cross-target WebDAV move;
- Nextcloud physical certification;
- ownCloud physical certification.

Nextcloud and ownCloud remain **UNVERIFIED**, not unsupported by definition; v0.18.0 simply does not claim physical compatibility evidence for them.

## Upgrade

No migration is required for existing Local/SFTP/S3 users. MSRV stays Rust 1.88.

For WebDAV, add one or more `[[webdav.targets]]` entries to `~/.config/arx/arx.toml` and provide the Basic-auth password through the OS keyring or the target-scoped environment variable. After installation:

```bash
arx --version
```

must report:

```text
arx 0.18.0
```
