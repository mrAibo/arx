# ARX v0.24.0

v0.24.0 is the focused **SFTP → SFTP Workspace Sync** release. It extends the
existing Compare → Preview → Execute → Verify workflow to same-host and
cross-host SFTP roots without introducing a second synchronization engine or
pretending that cross-host transfer is a server-side copy/rename. MSRV remains
**Rust 1.88**; ARX remains Linux-only with the published **Linux x86_64** target.

The immutable tag and live GitHub Release state remain authoritative for actual
publication; this release note does not infer publication merely from source-tree
version metadata.

## Highlights

### SFTP → SFTP Workspace Sync

ARX can now synchronize one SFTP workspace root to another using the same frozen
Preview and post-execution verification model already used by the existing
Local/SFTP directions.

- Exact source and destination SFTP host/path identities remain authoritative.
- Same-host different-root and cross-host roots are both supported.
- File content moves through bounded remote → ARX → remote streaming using the
  existing SFTP transfer authority.
- ARX does not claim a server-side SFTP copy/rename primitive that does not exist.
- SFTP directory creation and deletion reuse the existing provider mutation seams.
- Update and Mirror consequences remain frozen in Preview before execution.
- Stale source or destination evidence fails closed before mutation.
- Deterministic action ordering, cancellation, partial completion, journal truth,
  retry/recovery classification, and post-execution destination verification are
  retained.

### Existing authority model retained

The feature reuses the existing workspace-sync controller, `ProviderRegistry`,
Transfer Queue / Job lifecycle, retry authority, journal, mutation seams, and
verification model. It does **not** introduce a second provider registry,
synchronization engine, scheduler, retry engine, JobManager, or secret store.

Cross-host SFTP transfer remains a copy workflow. This release does not expand
SFTP → SFTP Move or general cross-provider Move semantics.

## Safety boundaries retained

- Provider-native existing-resource identity remains authoritative.
- Frozen Preview remains mandatory before destructive Mirror consequences.
- Ambiguous remote mutations are not blindly replayed.
- Cancellation and partial completion remain explicit states.
- Destination verification is separate from transfer completion.
- Cross-host SFTP transfer is never represented as server-side rename/move.
- WebDAV automatic HTTP mutation retry remains disabled.
- S3 Inspector remains read-only and keeps object-storage truth separate from
  fabricated filesystem-capacity semantics.

## Retained from v0.23.0

v0.24.0 retains the read-only S3 Object & Bucket Inspector shipped in v0.23.0,
including exact `HeadObject` facts, bounded paginated bucket/prefix LiveScan,
cancellation/partial truth, and real MinIO acceptance. The v0.22.0 WebDAV
recursive-operation surface and Apache / Nextcloud / ownCloud evidence remain
retained as well.

No configuration migration is required from v0.23.0.

## Not in this release

- SFTP → SFTP Move.
- General cross-provider Move.
- WebDAV → WebDAV recursive/cross-target copy or move.
- Multi-root recursive WebDAV delete.
- S3 synchronization or mutation expansion.
- Digest/Bearer WebDAV auth without concrete interoperability need.
- Metadata/property mutation without a demonstrated admin use case.
- Another major user-visible feature beyond the accepted SFTP→SFTP sync slice.

## Installation

Download your preferred artifact and `SHA256SUMS` from the GitHub Release and
verify:

```bash
sha256sum --ignore-missing -c SHA256SUMS
```

```bash
# Debian / Ubuntu
sudo apt install ./arx_0.24.0_amd64.deb

# Fedora / RHEL family
sudo dnf install ./arx-0.24.0-1.x86_64.rpm

# Portable tarball
tar xzf arx-v0.24.0-x86_64-unknown-linux-gnu.tar.gz
sudo install -m 755 arx-v0.24.0-x86_64-unknown-linux-gnu/arx /usr/local/bin/arx
```

Expected version output:

```text
arx 0.24.0
```

No configuration migration is required from v0.23.0.
