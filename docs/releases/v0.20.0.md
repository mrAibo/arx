# ARX v0.20.0

v0.20.0 is the **Storage, Transfer Control, and Native Packaging release**. It promotes
the product work merged after v0.19.0 without introducing a new runtime feature inside
the release-readiness slice itself.

MSRV remains **Rust 1.88**. ARX remains intentionally **Linux-only**. The published
binary target remains **Linux x86_64**.

## Highlights

### Local Storage Inspector (`Alt+U`)

ARX now includes a read-only, Linux-local `du++`-style storage inspector.

- parallel local traversal through `dua-core`.
- logical/apparent bytes and allocated/on-disk bytes remain distinct.
- sparse-file truth is preserved instead of collapsing both size concepts.
- symlinks are reported but never followed.
- hard links are de-duplicated by filesystem identity.
- deterministic top-file and subtree drill-down views.
- optional depth and same-filesystem traversal policy in the scanner model.
- permission/stat/traversal errors remain visible and make a result partial rather
  than silently exact.
- long-running scans use the existing JobManager and its cancellation token.
- unknown scan total stays unknown; no fabricated percent or ETA.
- the overlay is observability only: no delete/cleanup action was added.

### Filesystems (`Alt+D`)

A second read-only Linux view provides `df++`-style filesystem/mount visibility.

- mount topology comes from `/proc/self/mountinfo` rather than shelling out to `df`,
  `findmnt`, or `mount`.
- capacity and inode statistics come from `statvfs`.
- total, used, free, available, and reserved byte semantics remain distinct.
- inode totals/used/available stay distinct and unsupported values do not become fake
  percentages.
- category filtering covers Local / Network / Fuse / Special.
- deterministic sorting by mountpoint, size, used, available, usage, and type.
- autofs entries are not stat'ed in the default snapshot, avoiding observation-triggered
  automount side effects.
- an inaccessible/broken mount remains visible as unavailable instead of failing the
  entire snapshot.
- refresh is explicit/manual; there is no background polling loop.

### Transfer Center v2 (`Ctrl+Y`)

The existing transfer runtime now has a full keyboard-first control surface.

- deterministic Active / History / All filters.
- compact job list plus selected-job details.
- lifecycle state, source → destination, typed JobProgress, scheduler state,
  attempts-started, concurrency, and terminal error/result facts are shown from
  existing runtime truth.
- percentage is displayed only when a real denominator exists.
- byte rate/ETA are displayed only when existing byte progress supports them.
- Pause/Resume/Cancel call the existing TransferQueueRuntime; the UI does not directly
  manufacture JobManager state transitions.
- invalid actions such as pausing RetryWaiting/Cancelling/terminal jobs fail truthfully.
- terminal history presentation is bounded without changing JobManager retention.

The v0.19.0 Transfer Queue safety contract remains unchanged: automatic retry is
bounded to at most three total attempts and only explicit `SafeToRetry` outcomes are
automatically replayed. Ambiguous remote mutations are never blindly retried.

### Native Linux packages

GitHub Releases now publish three Linux x86_64 package formats from **one validated
release ELF**:

- `arx-v0.20.0-x86_64-unknown-linux-gnu.tar.gz`
- `arx_0.20.0_amd64.deb`
- `arx-0.20.0-1.x86_64.rpm`
- `SHA256SUMS` covering all three package artifacts

The release pipeline builds the Rust release binary once. tar.gz, Debian, and RPM are
then produced from that exact ELF. Validation extracts each format and requires the
packaged executable hash to match the original release binary hash.

Additional packaging guarantees:

- Debian runtime dependencies are derived from the exact ELF with `dpkg-shlibdeps`.
- Debian package ownership metadata is produced rootlessly.
- RPM packaging does not strip or rewrite the validated executable.
- RPM build-id link injection is disabled so the payload remains exactly inside the
  declared executable/documentation contract.
- tar/deb/rpm payload manifests fail closed on unexpected files or symlinks.
- package name/version/architecture and release metadata are validated before upload.
- publication reuses the validated artifacts without rebuilding them.

### Third-party licensing

The release workflow generates `THIRD_PARTY_LICENSES.html` with `cargo-about` from the
Linux Cargo dependency graph. Packaging fails if the report is absent or empty, and
the report is included in the tarball, Debian package, and RPM package.

## Installation

Download your preferred artifact and `SHA256SUMS` from the GitHub Release.

Verify the files you downloaded:

```bash
sha256sum --ignore-missing -c SHA256SUMS
```

### Debian / Ubuntu

```bash
sudo apt install ./arx_0.20.0_amd64.deb
```

### Fedora / RHEL family

```bash
sudo dnf install ./arx-0.20.0-1.x86_64.rpm
```

### Portable tarball

```bash
tar xzf arx-v0.20.0-x86_64-unknown-linux-gnu.tar.gz
sudo install -m 755 arx-v0.20.0-x86_64-unknown-linux-gnu/arx /usr/local/bin/arx
```

Then verify:

```bash
arx --version
```

Expected output:

```text
arx 0.20.0
```

## Upgrade notes

No configuration migration is required from v0.19.0.

Existing `[transfer] concurrency` configuration remains valid. Storage Inspector and
Filesystems are read-only Linux features and add no persistent state or destructive
migration step.

Users installing the native `.deb` or `.rpm` should prefer the package manager over
manually copying the tarball binary. The tarball remains the universal Linux x86_64
fallback.

## Safety boundaries retained

- destructive workspace sync still requires Preview.
- transfer retry remains phase-aware and bounded; ambiguous mutation != retryable.
- SFTP transactional copy and host-key verification behavior are unchanged.
- WebDAV automatic HTTP mutation retry remains disabled.
- Storage Inspector and Filesystems do not expose cleanup, delete, mount, remount,
  resize, or quota mutation actions.
- unknown/error/partial storage facts are not rendered as exact success.
- no new provider combinations are claimed merely because Transfer Center or storage
  views exist.

## Backend support inherited from v0.19.0

- **SFTP:** supported baseline with Remote Edit, managed SSH Host Manager, and
  transactional copy safety.
- **AWS S3 + MinIO:** PHYSICAL PASS / SUPPORTED MVP.
- **Moto:** EMULATED PASS.
- **Cloudflare R2 / Wasabi:** UNVERIFIED best-effort only.
- **WebDAV Apache mod_dav:** PHYSICAL PASS, W1–W18 / SUPPORTED MVP.
- **Nextcloud / ownCloud:** UNVERIFIED.
- **WebDAV auth:** Basic only.

## Deferred / not claimed

v0.20.0 does not add:

- native Windows or macOS support.
- Linux architectures other than x86_64.
- apt/yum repository hosting or package signing.
- WebDAV Digest/Bearer authentication.
- WebDAV F4 remote edit.
- recursive WebDAV transfer/delete or cross-target WebDAV move.
- Nextcloud/ownCloud physical certification.
- SFTP → SFTP workspace synchronization.
- generic cross-backend Move.
- recursive remote delete.
- binary remote editing.
- S3 POSIX-style filesystem capacity claims.

## Release validation

The v0.20.0 release candidate is accepted only when the exact release head passes:

- format and clippy (`-D warnings`).
- full Rust test suite.
- Rust 1.88 MSRV check.
- WebDAV physical acceptance.
- Transfer Queue real-MinIO safe-read retry acceptance.
- single release build.
- third-party license generation.
- tar/deb/rpm build and exact payload validation.
- packaged-binary identity + `--version` / `--help` smoke.
- three-entry `SHA256SUMS` verification.

The tag must point at the accepted merge SHA, and the tag-triggered publication job
must reuse the validated artifacts without rebuilding the Rust binary.
