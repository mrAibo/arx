# ARX v0.22.0

v0.22.0 expands the WebDAV recursive-operation surface from the one-way recursive
download introduced in v0.21.0 into a fuller, still deliberately bounded admin
workflow: recursive Local → WebDAV upload, safe recursive WebDAV deletion, and
multi-root F5 Copy for Local ↔ WebDAV. MSRV remains **Rust 1.88**; ARX remains
Linux-only with the published **Linux x86_64** target.

## Highlights

### Recursive Local → WebDAV upload

One selected Local directory can now be copied as one new WebDAV directory tree
through the existing F5 → preparation → `TransferPlanner` → transfer queue →
WebDAV executor authority.

- New-resource addressing uses target-relative `WebDavWriteTarget`; existing
  server-returned `WebDavObjectRef` / `WebDavCollectionRef` identities remain
  separate and authoritative for resources that already exist.
- A complete Local manifest is built before the first remote mutation, with the
  shared 50,000-descendant and depth-128 limits and checked total-byte arithmetic.
- Symlinks, special filesystem objects, unsafe non-UTF-8 components, and source
  shape changes fail closed before or during execution rather than being
  materialized implicitly.
- Linux file reads use root-relative no-follow descriptor traversal and validate
  the opened descriptor type/size plus final read length before upload.
- The destination root must be new. Root ownership is proven only by a definitive
  successful MKCOL; ambiguous root creation is recovery-required and is never
  followed by blind cleanup or retry.
- After proven root ownership, child failure/cancellation may clean up only that
  attempt-owned root. Cleanup failure is reported truthfully as RecoveryRequired.
- Pause/cancel checkpoints occur at mutation boundaries, including immediately
  before root creation and file PUT after Local reads.
- Progress is cumulative whole-tree bytes and preserves zero-byte/empty-directory
  truth.

### Safe recursive WebDAV delete

ARX can now delete one selected WebDAV collection recursively without delegating
unbounded recursive scope to the server.

- The selected root is frozen as an exact provider-native `WebDavCollectionRef`;
  display names never become delete addresses.
- A complete bounded exact manifest is built and then fully revalidated before
  the first DELETE.
- ARX deletes deepest descendants first and the selected root last.
- Before each collection DELETE, ARX performs a fresh exact `PROPFIND Depth: 1`
  empty proof, avoiding a knowingly recursive server-side collection delete.
- Object/collection DELETE uses exact raw href containment under the configured
  target authority.
- Cancellation, deterministic partial failure, ambiguous mutation, LOCK/423, and
  cleanup/recovery outcomes retain truthful completed-item counts and never cause
  blind replay.
- Apache destructive-safety acceptance covers cancellation after a successful
  child delete, real WebDAV locking, and ambiguous DELETE fault behavior.

### Multi-root F5 Copy for Local ↔ WebDAV

F5 can now copy multiple selected current sibling roots as **one queued transfer
job** in both Local → WebDAV and WebDAV → Local directions.

- Selection resolves only against current real rows from the active source pane;
  stale or ambiguous selections fail before enqueue.
- WebDAV source objects/collections keep exact provider-native href identities.
  Presentation names are destination components and job labels only.
- Mixed file + directory selections are supported, including nested trees, empty
  roots, Unicode/spaces, and zero-byte content.
- The batch contains existing single-root transfer specs and executes them
  sequentially through the existing concrete WebDAV provider authority; no new
  runtime, scheduler, provider registry, or retry engine is introduced.
- User-visible batch progress is top-level root `Items` progress, emitted only
  after definitive root completion. Child byte counters are not leaked across
  root boundaries.
- Pause/cancel is honored before each next root. A failure, cancellation,
  RecoveryRequired, or ambiguous mutation stops later roots immediately.
- Successfully completed earlier roots remain in place; ARX does not claim a
  cross-root rollback it cannot prove.

## Physical acceptance

The WebDAV product path remains physically certified on real providers:

- Apache mod_dav: W1–W18 plus recursive download, recursive upload, recursive
  delete, destructive delete safety, and Local ↔ WebDAV multi-root F5 Copy.
- Nextcloud `34.0.2-apache`: portable I1–I12 plus recursive download/upload/delete
  and multi-root F5 Copy.
- ownCloud `11.0.0`: the same portable acceptance family as Nextcloud.

The existing MinIO safe-read retry and real tmux/GNU Screen PTY acceptance lanes
also remained green on the exact accepted heads and on merged main.

## Safety boundaries retained

- WebDAV automatic HTTP mutation retry remains disabled.
- Ambiguous remote mutations are never blindly replayed.
- Provider-native existing-resource identity remains authoritative; display names
  never reconstruct remote hrefs.
- Secrets remain in the OS keyring/environment; Basic auth remains the shipped
  WebDAV auth path.
- There is still exactly one `TransferQueueRuntime`, `JobManager`,
  `ProviderRegistry`, scheduler/retry authority, and secret-store model.
- S3 remains object storage; ARX does not fabricate POSIX filesystem-capacity
  semantics for it.

## Not in this release

- Multi-root recursive WebDAV delete.
- WebDAV → WebDAV recursive/cross-target copy or move.
- SFTP → SFTP workspace sync.
- General cross-provider Move.
- Digest/Bearer WebDAV auth without concrete interoperability need.
- Metadata/property mutation.

## Installation

Download your preferred artifact and `SHA256SUMS` from the GitHub Release and
verify:

```bash
sha256sum --ignore-missing -c SHA256SUMS
```

```bash
# Debian / Ubuntu
sudo apt install ./arx_0.22.0_amd64.deb

# Fedora / RHEL family
sudo dnf install ./arx-0.22.0-1.x86_64.rpm

# Portable tarball
tar xzf arx-v0.22.0-x86_64-unknown-linux-gnu.tar.gz
sudo install -m 755 arx-v0.22.0-x86_64-unknown-linux-gnu/arx /usr/local/bin/arx
```

Expected version output:

```text
arx 0.22.0
```

No configuration migration is required from v0.21.0.
